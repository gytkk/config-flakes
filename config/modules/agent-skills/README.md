# Agent skills activation

The common Home Manager profile imports [default.nix](default.nix) to install or update skills for enabled Codex, Claude, and Pi agents during each switch. Codex or Pi enables the shared target once, and Claude enables its global copy target.

One invocation of [the installation adapter](../../../scripts/install-agent-skills.py) handles all selected targets after `linkGeneration` and, when Codex is enabled, `codexUserConfig`. Each external source resolves to one latest full SHA for that invocation, shared by every target. The module provides Node/npm, Git, and Python with the packaged canonical agent-core resources. Nix evaluation and builds do not fetch external skills; activation requires network access. Home Manager's `run` wrapper honors dry-run mode. Installation errors fail the switch and retain the adapter's backup and recovery safeguards.

After resolving external revisions, the adapter skips staging, license downloads, CLI installation, and backups when every target matches its last successful receipt. It compares the complete installation plan, including the CLI version, external revisions, local file contents and modes, ownership records, installed files, and selected CLI lock entries. Unchanged switches still check external source revisions. Missing or modified managed skills remain errors, and unowned same-name skills still require an explicit ownership handoff. An older installation without this metadata runs the full installation once. Failed operations do not provide a successful cache record.

Local source fingerprinting accepts regular files shared through Nix store hardlinks and records their content and modes. Installed skills and backups must contain independent regular files; symlinks and special files are rejected in both source and installation trees.

If installation damages an ownership record or CLI lock JSON, the failed receipt retains the original error and snapshots the damaged bytes. Restoration requires those bytes and the installed files to remain unchanged. A damaged lock is restored in full from its pre-installation bytes, including unrelated entries; valid locks still restore only selected entries. If metadata cannot be read for a byte snapshot, the receipt records the failure and restoration requires manual preservation rather than overwriting an unknown state.

CLI and Git commands run in separate process groups with a 300-second timeout. Before collecting installation state or releasing the installer lock, the adapter kills remaining processes in the command's group and waits up to five seconds to reap its launcher. This also applies to interruptions and commands whose launcher exits while a child keeps output pipes open. Descendants that deliberately create another session or process group are outside this cleanup boundary.

Before the first switch on an existing host, inspect and back up legacy skill links, files, CLI locks, and ownership records. Hand off conflicting legacy trees and unowned same-name skills explicitly; activation does not delete or adopt them automatically. A normal successful switch needs no separate installation command. Direct adapter commands remain available for isolated probes, recovery, and explicit SHA replay. See [Agent core installation and recovery](../../../agent-core/README.md#skill-설치와-복구) for the procedure and pending host verification.
